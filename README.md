ЛР 2

Задание: Создание базы данных PostgreSQL по теме работы, подключение БД к созданным трем шаблонам
Необходимо разработать структуру БД по выбранной теме и реализовать ее с учетом приведенных ниже требований. Использовать таблицу услуг на страницах разработанного приложения. Наполнить таблицы БД данными через Adminer.

Получение и поиск услуг, создание и публикация услуг (смена статуса) — через ORM. Для страницы плитки добавить кнопку логического удаления услуги (статус меняется на «удален») с помощью выполнения SQL-запроса UPDATE, без ORM. Всего шесть HTTP-методов: три GET, один POST для добавления новой карточки через ORM, второй POST для публикации карточки через ORM, еще один POST для удаления услуги через SQL курсор. При получении ленты с сервера БД должна возвращаться сразу только одна строка, не нужно выполнять фильтрацию в коде через массивы и т. д.

Для создания нужно указать название, фото, видео, нажать кнопку Далее. Для публикации нужно заполнить краткую информацию, оба поля по теме и нажать кнопку Опубликовать. При отсутствии услуги в статусе черновика у пользователя она создается только при нажатии кнопки Далее на странице добавление. Если такая услуга уже есть, то страница открывается с заполненными полями и кнопкой Опубликовать. Новые фото и видео в этой лабораторной работе не сохраняются в БД и не передаются на сервер, но по Далее нужно заполнять таблицу неверными url. Если в таблице есть пустые поля для url или файлы по ссылкам недоступны, то по умолчанию отображаются фото и видео, которые хранятся вместе с иконками на SSR сервере (они же отображаются на всех страницах для всех новых карточек). Удаленные услуги просматривать нельзя. Ставить лайки во второй лабораторной НЕ нужно, только отображать из БД.

Требования к БД:

Обязательно наличие 3 таблиц (каскадное удаление запрещено!):

услуг (наименование, краткое описание, статус черновик/опубликован/удален, url к изображению, url к видео, два поля по предметной области, дата создания дата и время, создатель; дата формирования дата и время)
лайки м-м пользователь-услуга (первичный и два внешних ключа)
пользователей
Обязательно наличие 3 услуг: черновик, удален, опубликован. У каждого пользователя не более одного услуги в статусе черновик. Названия таблиц и их полей должны соответствовать предметной области.
