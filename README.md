ЛР3

Задание: Создание веб-сервиса со всей итоговой бизнес-логикой (кроме авторизации), подключение его к БД и тестирование в insomnia/postman
Создание веб-сервиса для получения/редактирования данных из вашей БД. Требуется разработать все методы для реализации итоговой бизнес-логики вашего приложения. Для изображений услуг используйте Silo(MinIO).

Требования к веб-сервису

Методы и url в API должны соответствовать REST. Для списка услуг (как в первой лабораторной работе) нужно предусмотреть фильтрацию на бэкенде. Взаимодействие с БД через ORM. Записи в статусе удален клиенту не передаются.

Статусы нельзя менять с любого на любой: у создателя два разных метода, вернуть в черновик нельзя. В данной лабораторной работе пользователь создатель зафиксирован во всех методах — укажите его константой через функцию-singleton. Системные поля (идентификатор, статусы, создатель и модератор, даты создания, формирования и завершения) передавать с клиента для изменения запрещено. Они вычисляются на бэкенде через авторизацию и бизнес-логику. В начале адреса каждого метода добавьте /api

Домен сервиса:

GET список с фильтрацией (только опубликованные). Признак 0/1, если создатель услуги совпадает с текущим пользователем
GET лента (только опубликованные). Признак 0/1, если текущий пользователь лайкнул эту услугу
GET получение черновика (не более 1 записи для пользователя), ид не указывается
POST добавление + добавление файлов изображений и коротких видео (как файлов, а НЕ просто URL), названия файлов сохраняются в полях БД, а сами файлы — в Silo(MinIO). Названия файлов генерируются на латинице
PUT публикация (смена статуса)
DELETE удаление (только обратимое удаление). Только для этого пользователя
POST лайк (от текущего пользователя). Поле 0/1 (0 отменяет лайк, 1 ставит лайк)
Пользователь домена:

POST регистрация
POST аутентификация (заглушка для 4-й лабораторной)
POST деавторизация (заглушка для 4-й лабораторной)
